## 1. 采样与频率分辨率

采样必须满足奈奎斯特条件 \(f_s>2f_{max}\)，但工程设计通常需要更高过采样率，以给模拟抗混叠滤波器和数字算法留下余量。长度为 \(N\) 的 DFT 频率间隔为：

\[
\Delta f=\frac{f_s}{N}, \qquad f_k=k\Delta f
\]

增加 \(N\) 能改善频率栅格，但也增加延迟和 RAM 占用。先根据希望区分的最小频率差选 \(N\)，再检查这一帧数据的采集时间和处理时间能否被系统接受；FFT 长度不是越大越好。

### 送进算法前，先统一样本的含义

ADC 原始码通常带有直流偏置，直接送进 FFT 会让直流分量很大，甚至影响自动找峰。比较稳定的处理顺序是：先转为浮点或统一的定点格式，再减去本帧均值，按需要乘输入比例系数，最后加窗。这样 FFT、相关检测和 FIR 使用的是同一种“以零为中心”的样本，不必在每个算法里重复处理偏置。

若数据来自双通道采样，两个通道必须使用同一帧编号。不要把刚到的 A 通道与上一帧的 B 通道拼在一起做相位或阻抗计算；数值通常不会离谱，却会表现为缓慢漂移，很难排查。

## 2. DDS：相位累加器

软件 DDS 的核心是固定宽度相位累加器：

\[
P[n+1]=P[n]+K \pmod {2^B}, \qquad K=\frac{f_{out}2^B}{f_s}
\]

下面是一种 32 位相位累加器、固定采样率的写法：

```c
#define DDS_PHASE_BITS  32
#define DDS_SAMPLE_RATE 170000U
#define DDS_FREQ_TO_PHASE(f_hz) \
    ((uint32_t)(((uint64_t)(f_hz) << DDS_PHASE_BITS) / DDS_SAMPLE_RATE))
```

取相位高位作为 256 点波表索引，低位保留分数相位。DMA 半满和全满回调分别重填缓冲区，频率改变只需更新相位步进值，不必停掉 DAC；这也是输出连续波形最实用的做法。

波形切换或大幅改频时，最好把“待生效参数”与“正在使用参数”分开：主循环只更新待生效值，DMA 回调在一个半区写完的边界统一取用。这样可以避免同一半缓冲内前半段和后半段采用两套参数，从而产生肉眼可见的毛刺。

外部 AD9959 同样使用频率控制字：

\[
FTW=\operatorname{round}\left(\frac{f_{out}2^{32}}{f_{SYSCLK}}\right)
\]

14 位相位字满足 \(POW=\operatorname{round}(\phi\cdot16384/360^\circ)\)。这两条公式分别对应频率和相位寄存器，不应混用。

### 频率更新为何要在缓冲区边界生效

相位累加器的状态必须跨越 DMA 的前半与后半缓冲区连续保存。若每次填充缓冲区都把相位清零，输出频率虽然正确，连接处却会跳变。实现时让 Fill 函数从上一次结束的相位继续累加；参数改动只改变之后的步进值，不重置累计相位，除非明确需要重新同步相位。

## 3. 窗函数与幅值校正

非整周期截断会产生频谱泄漏。加窗后的 DFT 为：

\[
X[k]=\sum_{n=0}^{N-1}x[n]w[n]e^{-j2\pi kn/N}
\]

Hamming 窗为 \(w[n]=0.54-0.46\cos(2\pi n/(N-1))\)。窗会降低幅值，因此需要计算相干增益：

\[
CG=\frac{1}{N}\sum_{n=0}^{N-1}w[n], \qquad
A_{peak}=\frac{2|X[k]|}{N\cdot CG}
\]

```c
for (uint32_t i = 0; i < FFT_SIZE; ++i) {
    coherent_gain += window[i];
    fft_re[i] = centered_sample[i] * window[i];
}
coherent_gain /= FFT_SIZE;
peak_code = 2.0f * magnitude[peak] / (FFT_SIZE * coherent_gain);
```

峰值位于两个频点之间时，可用三点抛物线插值：

\[
\delta=\frac{1}{2}\frac{M_{k-1}-M_{k+1}}{M_{k-1}-2M_k+M_{k+1}},
\quad f=(k+\delta)\Delta f
\]

### FFT 的一帧分析按什么顺序做

一帧数据到达后，建议固定为以下顺序：检查是否削顶；去直流；乘窗；执行 FFT；计算复数模长；跳过直流和不关心的频段；找主峰；再做幅值和频率校正。把这些步骤拆成函数后，既可单独打印中间结果，也便于替换不同窗函数。

调试时，先用频率刚好落在整数频点的正弦波。此时不开窗也应只有一个明显主峰；确认频点和幅值正确后，再测试非整数频点、开窗和插值。这样一旦结果异常，能判断是采样频率、窗函数还是峰值搜索出了问题。

## 4. 谐波与 THD

若 \(A_1\) 为基波幅值，\(A_h\) 为第 \(h\) 次谐波，则：

\[
THD=\frac{\sqrt{A_2^2+A_3^2+\cdots+A_H^2}}{A_1}\times100\%
\]

实际程序应在每个理论谐波频点附近搜索局部峰值，防止频率插值误差把能量分散到邻近频点；还要检查谐波是否超过奈奎斯特频率。

### THD 结果何时不该显示

当基波幅值太小、ADC 已削顶、主峰靠近奈奎斯特边缘，或者高次谐波超出可采样频段时，THD 没有可靠意义。接口最好返回有效标志，而不是强行给出百分比。对稳定性要求较高时，还可以连续计算几帧，只有结果变化落在允许范围内才更新显示值。

## 5. Hilbert 正交与任意移相

理想 Hilbert 变换让正频率分量移相 \(-90^\circ\)。有限长 FIR 产生正交分量 \(Q[n]\)，原信号延迟 \((L-1)/2\) 点得到对齐的 \(I[n]\)：

\[
y[n]=I[n]\cos\phi-Q[n]\sin\phi
\]

关键实现可以写成：

```c
for (int j = 0; j < FIR_N_TAPS; ++j)
    q += Hilbert_FIR_Coeffs[j] * history[head - j];

float i_delayed = history[head - FIR_DELAY];
output[n] = i_delayed * cos_phi - q * sin_phi;
```

这里必须补偿 FIR 群延迟，并为块间卷积保留 `L-1` 个历史样本。浮点实现适合先验证幅值、相位和稳定性；只有在 RAM、速度或功耗确实成为瓶颈时，再评估 Q15/Q31。过早切到定点，往往会把量化、缩放和溢出的问题与算法问题缠在一起。

### FIR 的状态不能跟着数据块重置

FIR 每次计算都依赖前面的样本。块处理时，新的数据块前面要接上上一块末尾保留的历史样本；若每收到一块就清空历史，块与块交界处会出现不连续，移相或滤波效果会周期性变差。最简单的验证方式是输入连续正弦波，观察每个数据块边界附近的输出是否平滑。

## 结果是否可信

DSP 模块调试时，建议先用已知的正弦、双音和直流偏置做输入，再看频率、幅值和相位是否分别符合预期。不要只看一张频谱图：记录采样率、帧长、窗函数、峰值频点、输入幅值和处理耗时，之后才能解释一次异常结果。
