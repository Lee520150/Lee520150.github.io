## 1. 驱动分层

一个可复用器件驱动至少分成三层：

1. **总线层**：SPI/I2C/UART 读写、片选、超时和错误码。
2. **寄存器层**：地址、位域、字节序、复位和初始化序列。
3. **业务层**：设置频率、读取距离、刷新屏幕等面向任务的接口。

驱动文件不应直接拥有整个 `main()` 的状态。推荐在句柄中保存 HAL 外设指针、GPIO 和配置，使同一驱动可以连接不同实例。

### 句柄里应保存哪些内容

驱动句柄至少应保存总线句柄、片选或复位引脚、设备地址和必要配置。这样驱动函数不需要依赖全局变量，也能在同一块板子上管理多个同类器件。业务层只接触“设置频率”“读取数据”一类接口，不需要知道某个寄存器用了几字节。

初始化函数建议按“硬件复位、确认身份、写默认配置、读回验证、标记就绪”的顺序执行。任一步失败都不要把设备标为可用；后续调用先检查就绪标志，可以避免总线异常后继续输出旧数据。

## 2. SPI：事务和字节序

先从数据手册确认 CPOL、CPHA、位宽、最高时钟、片选时序和字节序。常见的“命令字节 + 大端 32 位数据”事务可以写成：

```c
uint8_t tx[5] = {
    (uint8_t)(0x80U | address),
    (uint8_t)(value >> 24), (uint8_t)(value >> 16),
    (uint8_t)(value >> 8),  (uint8_t)value
};

HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_RESET);
HAL_SPI_Transmit(&hspi3, tx, sizeof(tx), HAL_MAX_DELAY);
HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_SET);
```

调试第一步不是跑完整业务，而是写入测试图样再读回，先验证模式、线序和片选。若读回全是 0、全是 1 或固定值，先检查片选是否真的拉低、MISO 是否悬空、SPI 模式是否匹配；不要急着修改寄存器逻辑。

一次事务结束时，无论成功还是超时，都要恢复片选状态。把片选拉低、收发、等待就绪、拉高封装成一个函数，可以避免异常返回时遗漏拉高，导致下一次通信从错误状态开始。

## 3. AD9959：寄存器更新边界

AD9959 驱动包含 `CS`、`MASTER_RESET` 和 `IO_UPDATE` 三类控制。寄存器写完并不一定立即生效，必须在一组参数写完后产生 `IO_UPDATE` 脉冲，避免频率、相位、幅值分批改变。

频率字、相位字和幅度字分别由 FTW、POW、ACR 控制。多通道更新时应先选择通道、写参数，最后统一更新；扫频时把通信操作与固定周期调度分开。

### 参数更新需要一个明确的提交动作

许多可编程器件不会在每写一个寄存器后立刻改变输出，而是等到某个更新脉冲或同步命令到来。把频率、相位、幅值等相关参数一次性写完，再统一提交，可以避免中间态出现在输出端。扫描频率时，把写寄存器的节奏与采样节奏分开；总线变慢时，不应拖住实时回调。

## 4. I2C：传感器接入

温湿度、光照、姿态、气压和测距器件虽然测量对象不同，接入步骤基本一致：

- 上电等待和软复位。
- 读取器件 ID，确认地址和总线连接。
- 写配置寄存器并读回验证。
- 启动测量，等待数据就绪。
- 按数据手册拼接原始码，再做比例和温漂补偿。

I2C 地址在 HAL 中通常需要左移一位；是传入 7 位地址还是 8 位地址必须在驱动接口中统一，不能每个调用点自行猜测。遇到偶发 NACK 时，先确认上电等待、上拉电阻、总线速率和器件忙状态；反复重试只能掩盖问题，不能替代诊断。

## 5. UART：中断接收与帧解析

单字节中断接收、状态机拼帧和命令队列是很容易起步的组合。回调只把字节送入解析器并立即重新挂接接收：

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart == dgus_uart) {
        DGUS_ProcessByte(dgus_rx_byte);
        HAL_UART_Receive_IT(dgus_uart, &dgus_rx_byte, 1U);
    }
}
```

完整帧解析必须处理帧头、长度、命令、地址和负载，并在非法长度或超时后回到等待帧头状态。长度字段应设置上限，不能按收到的任意长度写入缓存；这是串口协议中最基本也最容易被漏掉的边界检查。

发送端可用队列隔离 UI 刷新与实时测量，避免串口阻塞采样链。队列满时，测量结果可只保留最新一条，状态日志则允许丢弃低优先级信息；关键是把策略写清楚，而不是让发送函数在任何位置无限等待。

## 6. 显示和射频开关

显示屏、开关和指示器属于 GPIO/SPI 类低速控制器件。此类驱动的重点是把端口映射、复位时序、刷新区域和业务状态分开。屏幕全帧刷新耗时较长，应优先局部更新；开关切换后应留出稳定时间再采样。

## 驱动验收表

| 项目 | 验证内容 |
| --- | --- |
| 电气 | 电平、电源、上拉、模拟地与数字地 |
| 总线 | 模式、速率、字节序、片选与超时 |
| 身份 | ID/状态寄存器可重复读取 |
| 配置 | 写入后读回，复位后恢复默认值 |
| 边界 | 最大最小参数、断线、忙状态与校验失败 |
| 时序 | 逻辑分析仪波形与数据手册一致 |

## 配置与验证顺序

先确认电气连接，再读设备 ID；随后做最小读写测试，最后才接入业务逻辑。每增加一层，都保留可观察的证据，例如读回寄存器、串口日志或逻辑分析仪波形。这样发生问题时，能准确停在失败的那一层，而不是从整套系统里盲猜。
